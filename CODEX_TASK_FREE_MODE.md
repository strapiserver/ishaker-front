# Codex: бесплатный режим машины из портала

23.08.2026. Бэкенд готов на **dev-Strapi** (`admin@100.114.99.86:~/DEV/ishaker/strapi`),
на прод ещё не промоучен. Нужен UI: **тумблер + поле «минуты»** на странице машины.

## Зачем

Бесплатный режим (FREE MODE) на Shaker S включается кнопкой на двери и живёт **15 минут** —
таймер зашит в прошивку контроллера, из софта его не изменить. Владельцу точки этого мало:
нужен и бесплатный день на открытии, и «навсегда» для внутренней машины в офисе. Патч киоска
удерживает режим сам, а включать его теперь можно **с двух сторон**:

1. **портал** — этот таск;
2. **сервисное меню самого киоска** — тумблер и поле в разделе приложения (делается патчем).

Обе стороны пишут в одно и то же место в Strapi, поэтому UI обязан показывать то, что
реально стоит на машине, а не то, что последним ввёл пользователь.

## 1. Что уже есть в Strapi (менять не надо)

### поля `machine`

| поле | смысл |
|---|---|
| `free_mode` (bool) | включён ли режим |
| `free_mode_minutes` (int 0..3600) | длительность окна в минутах. **`0` = навсегда** |
| `free_mode_started_at` (datetime) | когда окно стартовало; ставит **сервер**, не клиент |
| `free_mode_rev` (int) | счётчик правок, растёт на каждую запись с любой стороны |
| `free_mode_source` (`portal` \| `machine`) | кто менял последним |

Часы машин на флоте расходятся на часы, поэтому Strapi хранит **намерение**, а обратный
отсчёт крутит сам киоск. Сервер на каждый запрос пересчитывает остаток по СВОИМ часам.

### эндпоинт для портала

```
PUT /api/machines/:id/free-mode        Authorization: Bearer <service JWT>
{ "enabled": true, "minutes": 45 }     // minutes: целое 0..3600, 0 = навсегда
```

Ответ:

```json
{
  "id": 114,
  "accepted": true,
  "state": {
    "enabled": true,
    "minutes": 45,
    "remainingSeconds": 2681,   // null = навсегда или выключено
    "startedAt": "2026-08-23T18:04:12.000Z",
    "rev": 7,
    "source": "portal",
    "expired": false
  }
}
```

Необязательный `base_rev` в теле включает защиту от гонки: если на машине уже другой `rev`,
ответ придёт с `accepted:false`, `reason:"stale_rev"` и актуальным `state` — показать его и
не ретраить молча.

**Никогда не писать `free_mode*` через обычный `PUT /api/machines/:id`.** `started_at` и `rev`
ведёт сервер; прямая запись сломает и отсчёт, и разрешение конфликтов.

Текущее состояние отдаёт обычный `GET /api/machines/:id` (поля выше), но `remainingSeconds`
там нет — считать на клиенте как `startedAt + minutes*60000 - now`, либо брать из ответа PUT.

## 2. Что сделать

### 2.1 BFF-роут `pages/api/portal/machines/[id]/free-mode.ts`

По образцу соседей (`cells.ts`, `inventory.ts`):

* `getPortalSessionFromApiRequest` → 401 без сессии;
* машина обязана быть в `session.machines` → иначе 403 `machine_access_denied`;
* `GET` — вернуть состояние (из `GET /api/machines/:id` через `requestStrapiRestAsService`)
  плюс посчитанный `remainingSeconds`;
* `PUT` — провалидировать вход и позвать `PUT /api/machines/:id/free-mode`;
* прокинуть `accepted:false` наверх как есть (200 + тело), это не ошибка сервера.

Валидация на входе (до Strapi): `enabled` — boolean; `minutes` — **целое** 0..3600,
пустое поле = 0. Дробное, отрицательное, `>3600`, строка-мусор → 400 `bad_minutes`.

### 2.2 UI на странице машины

`pages/machines/[id].tsx` (клиентский портал) и `pages/admin/machines/[id].tsx` (админка) —
блок «Free mode» рядом с остальными настройками машины:

* **тумблер** on/off;
* **числовое поле «минуты»** с подписью-подсказкой `0 = forever`, max 3600;
  поле активно и когда режим выключен (задать длительность заранее);
* когда режим включён и `minutes > 0` — строка `Ends in 44:41`, тикающая раз в секунду
  из `remainingSeconds` (локальный таймер, без опроса сервера каждую секунду);
* когда `minutes = 0` и включено — вместо таймера `No time limit`;
* строка происхождения: `Set from the kiosk` / `Set from the portal` по `source`;
* рефетч состояния раз в 30 с и после каждого сохранения — режим могли выключить
  на самой машине, и UI обязан это подхватить;
* пока PUT в полёте — блокировать контролы, не делать оптимистичный рендер: сервер может
  ответить `stale_rev` и вернуть другое состояние.

Предупреждение под блоком, коротко: **пока режим включён, все напитки бесплатны, продажи
пишутся с нулевой суммой.** Без восклицательных знаков и капса.

### 2.3 Задержка применения

Киоск забирает настройки опросом раз в 5 минут, поэтому после сохранения показать
`Applies on the machine within ~5 minutes`. Не изображать мгновенное применение.

## 3. Приёмка

- [ ] Включение на 45 минут: `state.enabled=true`, таймер тикает, через 45 минут портал
      показывает выключено (сервер сам считает окно истёкшим, даже если киоск офлайн).
- [ ] `minutes=0` + включено → `No time limit`, `remainingSeconds:null`.
- [ ] 3601 и `-1` не уходят в Strapi, поле подсвечено ошибкой.
- [ ] Чужая машина в URL → 403, своя → 200.
- [ ] Выключение с машины (сервисное меню) видно в портале после рефетча, `source:"machine"`.
- [ ] Обычный `PUT /api/machines/:id` из портала не содержит ни одного поля `free_mode*`.

Вопросы по контракту — в `~/DEV/ishaker/strapi/src/api/machine/controllers/machine.js`,
секция `FREE MODE` (там же правила `rev` и что именно рестартит отсчёт).
